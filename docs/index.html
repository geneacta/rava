geneacta / rava

Rust, écrit avec la
syntaxe de Java.

Rava ne réinvente rien. Les types, la propriété, l'emprunt, les durées de vie, les traits, Option, Result, Send et Sync sont exactement ceux de Rust. Seule la syntaxe change : on écrit des classes, des interfaces, des switch et des annotations.

fichier.rava ──▶ ravac · syntaxe ──▶ fichier.rs ──▶ rustc · sémantique ──▶ binaire

Par où commencer

Deux chemins vers la même langue. Choisissez celui d'où vous venez.

Le principeVotre syntaxe, un autre contrat

Vous écrivez des classes, des interfaces, des méthodes, des switch. Rien à désapprendre de ce côté. Ce qui change, c'est que le compilateur ne vous laissera plus mentir sur la mémoire : qui possède quoi, qui a le droit de modifier, jusqu'à quand une référence est valide.

En échange, il n'y a plus de NullPointerException, plus de ConcurrentModificationException, plus de fuite par référence oubliée, et pas de ramasse-miettes.

Étape 1Ce qui disparaît

Quatre habitudes Java n'ont aucun équivalent. Rava les refuse, avec un message qui dit quoi écrire à la place.

Vous écriviezVous écrirezPourquoi
nullOption<T>l'absence devient un cas du type, pas une bombe
try / catch / throwResult<T, E> + .q()l'échec est une valeur de retour, visible dans la signature
class A extends Bcomposition + interfacepas de sous-typage entre structures
instanceofswitch sur une enumles cas sont fermés et vérifiés à la compilation

En revanche, plusieurs réflexes Java que l'on croit perdus sont simplement traduits : x++ même en expression, >>>, super.m(), et finalize() — qui devient un Drop déterministe, donc qui s'exécute vraiment. Le détail est dans la section « masques ».

Étape 2Le seul concept vraiment neuf : la propriété

En Java, toute variable est une référence et le ramasse-miettes tranche. En Rava, chaque valeur a un propriétaire unique. Passer une valeur, c'est soit la donner, soit la prêter. Ce choix s'écrit avec une annotation.

ÉcritureSignificationCe que vous pouvez faire
String son vous donne la valeurtout, y compris la détruire — l'appelant l'a perdue
@Ref String son vous prête en lecturelire ; plusieurs prêts simultanés possibles
@Ref @Mut String son vous prête en écrituremodifier ; un seul prêt à la fois

Le réflexe

Par défaut, une méthode emprunte en lecture. Ajoutez @Mut quand elle modifie, @Owned quand elle consomme. Si vous vous trompez, rustc vous le dira — dans les termes de Rust.

Étape 3Le switch devient un vrai filtrage

La forme flèche que vous connaissez (Java 14+) devient le match de Rust : elle déconstruit les valeurs, accepte des gardes, et le compilateur exige que tous les cas soient couverts. 

var libelle = switch (msg) {
    case Message.Quitter                          -> "fin";
    case Message.Bouger(var x, var y) when x == y -> "diagonale";
    case Message.Bouger(var x, var y)            -> "déplacement";
    case 1 ... 5                                 -> "petit";
    default                                       -> "autre";
};

Oubliez un cas : le programme ne compile pas. C'est la différence entre un switch et un filtrage.

Étape 4Deux commodités que Java n'a pas

Rava ajoute unless et les opérateurs logiques en toutes lettres, parce qu'une condition se lit mieux qu'elle ne se déchiffre.

Huit mots réservés : and, or, xor, nand, nor, xnor, implies, not. Précédence logique classique — implies le plus lâche, not le plus serré — et ravac parenthèse ce qu'il faut pour que le sens écrit soit le sens compilé.

Étape 5Installez l'outillage

Votre IDE sait déjà colorer un .rava : c'est du Java valide, il suffit d'associer l'extension au langage Java. Pour le reste — erreurs en direct, survol qui explique ce que chaque annotation devient en Rust, complétion, corrections rapides — installez le serveur de langage : 

cargo install --path crates/rava-lsp

Il fonctionne dans VS Code, IntelliJ, Neovim, Helix, Zed, Sublime et Emacs. Le survol est le meilleur compagnon d'apprentissage : passez la souris sur @Mut, sur implies, sur null — il vous dit ce que ça devient, ou pourquoi c'est refusé. Réglages par éditeur dans editors/README.md.

Étape 6Votre premier programme

  1. Écrivez un .rava Une classe, un public static void main(String[] args), et System.out.println("{}", x) — le format est celui de Rust.
  2. ravac emit Mon.rava Lisez le Rust produit. C'est le meilleur cours de Rust disponible : votre propre code, traduit.
  3. ravac run Mon.rava Compile avec rustc et exécute. Les erreurs qui remontent sont celles de Rust.
  4. Quand ça coince Lisez IMPOSSIBLE.md : si la construction y figure, ce n'est pas vous, c'est Rust qui ne le fait pas.

Le principeRien à réapprendre, un dictionnaire à lire

La sémantique est identique : ravac ne fait aucune analyse. Il traduit des formes et passe le résultat à rustc. Vos réflexes de propriété, d'emprunt et de durée de vie sont exactement les bons.

La question n'est donc jamais « est-ce que ça marche pareil ? » — oui — mais « comment ça s'écrit ? ». Voici le dictionnaire.

Dictionnaire 4Ce que Rava ajoute

Trois formes n'existent pas en Rust. Elles se désucrent à la traduction, sans coût.

RavaRust généré
unless (c) { }if !c { } — avec inversion de l'opérateur : unless (x > 0) donne if x <= 0
else unless (c) { }else if !c { }
a and b · a or b · a xor ba && b · a || b · a ^ b
a nand b · a nor b · a xnor b!(a && b) · !(a || b) · !(a ^ b)
a implies b!a || b — associatif à droite
not a!a — lie plus lâche que ==
Attention à la précédence

L'ordre des mots est celui de la logique (implies < or < xor < and < not), pas celui des symboles Rust où ^ lie plus fort que &&. ravac parenthèse en conséquence : a xor b and c produit a ^ (b && c).

OutillageUn serveur de langage, partout

cargo install --path crates/rava-lsp

rava-lsp partage le lexer, le parser et le générateur de ravac : ce que l'éditeur souligne est exactement ce que le compilateur refusera. Diagnostics, survol, complétion, plan du fichier, corrections rapides — dans VS Code, IntelliJ (via LSP4IJ), Neovim, Helix, Zed, Sublime et Emacs. Réglages dans editors/README.md.

Ce qu'il ne fait pas encore : renommage, aller à la définition, formatage, et la remontée des erreurs de rustc — emprunt, durées de vie — sur le .rava. Pour celles-là, ravac check reste le passage obligé.

Le piègeLes identifiants ne sont pas renommés

camelCase reste camelCase dans le Rust produit — le fichier généré porte #![allow(non_snake_case)]. C'est délibéré : cela permet d'implémenter un vrai trait Rust (fmt, next, drop) sans que le nom ne se déforme en route. Nommez vos méthodes de trait comme Rust les attend.

Les masquesCe qui n'a pas de forme Java directe

Quelques constructions Java n'ont pas d'équivalent immédiat en Rust — et l'inverse. Rava les traduit vers ce que vous écririez à la main : même sémantique, même coût, aucune approximation.

RavaRust généré
x++ / x-- en expression{ let t = x; x += 1; t }
++x / --x en expression{ x += 1; x }
a >>> bun trait UShr inséré dans le fichier, qui passe par le type non signé de même largeur — émis seulement s'il sert
finalize()impl Drop for T { fn drop(&mut self) }
super.m(args)Trait::m(self, args)
Deux réserves, documentées

x++ en expression relit la place deux fois : a[f()]++ appellerait f() deux fois. Et super.m() ne vaut que pour une méthode non redéfinie — sur celle que vous redéfinissez, Trait::m(self) repasserait par votre propre implémentation. Rava refuse ce cas au lieu de produire une boucle.

Ce qui manqueLes vraies limites

Il ne reste rien de significatif du côté Rust : durées de vie, types associés, génériques constants, dyn, impl Trait, unsafe, pointeurs bruts, async, macros, tableaux de taille fixe — tout a une forme Java. Pour le reste, @Rust("…") et Rust.expr("…") insèrent du Rust brut, délibérément visibles dans le code.

La liste inverse — ce que Java sait faire et que Rava refuse — est dans IMPOSSIBLE.md. Elle ne vous surprendra pas : c'est la liste de ce que Rust ne fait pas.
